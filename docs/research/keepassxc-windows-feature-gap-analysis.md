# KeePassXC Windows Feature Gap Analysis

## Executive summary

KeePass Nexus has the beginnings of a Windows KDBX desktop client: it can open and create a local vault, unlock it with a master password and optional key file, browse groups, manage basic entries, search, generate passwords, and save changes. It also supports entry icons (including uploaded images and downloaded favicons), tags, and expiration metadata.

It is not yet feature-comparable to KeePassXC for Windows. The largest gaps are database compatibility and lifecycle tooling, full group and entry management, attachments and entry history, TOTP, Auto-Type, browser integration, import/export, merge/synchronization, and security/configuration controls. In particular, the current Rust dependency documents KDBX 4 writing as experimental, and the app only exposes KDBX 4 saving; this is a release-readiness and interoperability blocker, not merely a missing convenience feature.

This comparison prioritizes user-visible Windows functionality rather than source-code or UI parity. “Partial” means Nexus has a related capability but not the complete KeePassXC workflow or compatibility. “Not Windows-targeted” identifies KeePassXC platform-specific features that should not be treated as Windows parity requirements.

## Feature comparison

| Area | KeePassXC Windows capability | KeePass Nexus status | Gap / implication |
|---|---|---|---|
| KDBX open and unlock | Opens compatible KeePass KDBX databases; supports password and key-file credentials and database key configuration. | **Partial.** Opens KDBX 3/4 and accepts a master password and optional key file. | Expand compatibility testing to real KeePassXC databases, key-file variants, and uncommon metadata. Add supported credential types only where intentionally in scope. |
| Windows Hello quick unlock | Can protect quick-unlock data with Windows Hello after an ordinary database unlock. | **Missing.** No Windows Hello or secure quick-unlock workflow. | Treat as an optional convenience layered over the full database key, not a replacement for recovery-capable credentials; bind and clear it safely on lock/database changes. |
| Database creation and writing | Creates, reads, and saves KDBX 3 and KDBX 4 databases; exposes database format, encryption, and key-derivation settings. | **Partial; high risk.** Creates/saves through the Rust facade, but only KDBX 4 save is exposed; the pinned crate describes KDBX 4 writing as experimental. | Establish reliable KDBX 3/4 write behavior and cross-application round-trip fixtures before claiming compatibility. Add deliberate cipher/KDF choices and safe migration behavior. |
| Multiple databases | Opens several databases in tabs, switches between them, locks individual or all databases, and tracks recent databases. | **Missing/partial.** The controller owns one active file/session; no database tabs or recent-database manager are exposed. | Add multi-database lifecycle, dirty-close prompts, per-database lock state, recent files, and recovery from failed unlocks. |
| Database settings and key changes | Database settings include metadata, security/KDF, recycle-bin, and other database-level options; users can change database credentials/settings. | **Missing.** Settings currently cover theme, inactivity timeout, and About/version. | Add database metadata and master-key/KDF/cipher management, with clear warnings and safe-save handling. |
| Backup and safe save | Supports on-demand/pre-save backups and configurable safe, temporary, or direct-write save behavior. | **Missing/partial.** The client saves the active local file but exposes no backup policy or recovery UI. | Add configurable backups and test interrupted writes, disk-full errors, and recovery before production use. |
| Groups and hierarchy | Browses, creates, edits, moves, sorts, and deletes groups; supports group icons and group-level properties. | **Partial.** Nested groups can be browsed and created; entries can be moved. Full group editing/maintenance is not exposed. | Add rename/edit, move, delete with descendant confirmation, icons, ordering, and group properties; preserve tree semantics on KDBX round trips. |

| Tags | Assigns and manages tags, displays tag views, and filters entries by tag. | **Partial.** User-defined whitespace-separated tags are stored natively and included in search. | Add tag browsing/filtering and bulk tag management if parity with KeePassXC's tag view is desired. |
| Expiration | Stores expiration metadata and exposes entry expiration operations and database views. | **Partial.** Native expiry metadata, date/time selection, and relative presets are present. | Add expiry-aware filtering/indicators and confirm disabled-expiry timestamps and timezone conversions remain interoperable. |
| Attachments | Stores files with entries and provides attachment editing/access. | **Missing.** No attachment UI or CRUD path is exposed. | Implement protected KDBX attachment storage, safe file extraction/opening, size/error handling, and attachment round-trip tests. |
| Custom attributes and field references | Supports arbitrary protected/unprotected entry attributes, foreground/background colors, and references between entries/fields. | **Missing.** The editor exposes only standard fields plus the implemented tags/expiry/icon metadata. | Add extensible custom fields, entry colors, and reference resolution without leaking protected values in summaries/search. |
| Entry history and restore | Keeps prior entry revisions and supports viewing/restoring history; the source UI includes dedicated history editing. | **Partial.** The Rust update path uses the underlying history-tracking API, but the app has no history browser or restore workflow. | Expose history, restore, retention/cleanup, and history-safe save behavior. |
| Recycle bin and recovery | Supports a configurable database recycle bin and entry-history restoration. | **Missing/partial.** History is maintained by the underlying update API but there is no recycle-bin or restore UI; deletion is exposed directly. | Add a configurable recycle bin and explicit restore/permanent-delete flows before expanding destructive operations. |
| Search | Searches across entries with field modifiers, wildcards, logical operators, tags, and saved/dynamic searches. | **Partial.** A simple query searches available entry fields and tags. | Match supported fields/semantics, add group/tag filters, query options, and saved/dynamic searches; test protected/custom fields against expected privacy behavior. |
| Password generator | Configurable character and passphrase generation with profiles/options and direct entry workflows. | **Partial.** Character and passphrase modes, entropy feedback, show/hide, refresh, copy, and clipboard clearing exist. | Compare advanced rules (character sets, exclusions, length/word options, profiles, and history) and add only the workflows required for the target parity level. |
| TOTP | Stores TOTP settings, generates codes, and supports setup/export workflows. | **Missing.** No TOTP field setup, QR provisioning, code generation, or copy workflow. | Add encrypted/native-compatible TOTP attributes, time-step generation, provisioning, and clock/error handling. |
| Auto-Type | Types credentials into other Windows applications using global and per-entry sequences, including field-specific sequences. | **Missing.** No global shortcut, sequence editor, or OS-level typing workflow. | A substantial Windows integration: define the threat model, secure target-window handling, sequence format, and keyboard navigation before implementation. |
| Browser integration and passkeys | Integrates with supported browsers for autofill, credential save/update, and passkey workflows. | **Missing.** No extension protocol, browser connection, autofill, or passkey support. | Build a companion extension and authenticated local/native messaging protocol; implement passkey storage/import only with explicit browser and platform scope. |
| Hardware security keys | Supports YubiKey/OnlyKey challenge-response key components. | **Missing.** Only password and key file are exposed. | Add hardware challenge-response to the KDBX key-composition path, including supported-device handling and recovery guidance. |

| Import/export | Imports CSV and supported password-manager/KeePass formats; exports database data to CSV, XML, and HTML. | **Missing.** The app opens/saves KDBX but has no import/export wizard. | Add previewable mappings, protected-field warnings, duplicate handling, and tests for lossless KDBX round trips. Treat plaintext exports as a sensitive operation. |
| Merge and synchronization | Merges database changes and supports remote storage/synchronization and KeeShare shared-database workflows. | **Missing.** The current client reads/writes a selected local file and has no merge/conflict workflow. | Add a merge engine and conflict UI before cloud/remote sync; never overwrite concurrent edits silently. Treat sync providers and KeeShare as separate integrations. |
| Database reports | Provides database reports, including password-health and statistics workflows (and optional breach-check reporting). | **Missing.** No report or audit views. | Add local password-strength/reuse/age reports first; make any network-backed breach check opt-in and explicit about data sent. |
| Clipboard and secret handling | Offers copy actions for common fields and custom attributes, plus clipboard clearing and lock/security controls. | **Partial.** Passwords are masked by default and generator copy/clear is available. | Add consistent copy actions for entry fields and configurable auto-clear; handle clipboard failure visibly and test that locks clear sensitive UI state. |
| Locking and OS protections | Configurable inactivity lock, manual lock, lock-all, security settings for session/minimize events, and Windows screen-capture blocking with an override. | **Partial.** Inactivity auto-lock and best-effort Windows capture exclusion exist. | Add manual/lock-all controls and review lock behavior on suspend, session lock, user switch, and app close. Document capture protection as best effort and make the user-visible policy clear. |
| Preferences, shortcuts, appearance | Broad application preferences, keyboard shortcut customization, window/view configuration, startup/tray behavior, and integration settings. | **Missing/partial.** Theme and inactivity timeout are exposed; settings are otherwise sparse. | Build a settings model and UI for supported features, keyboard shortcuts, startup/file behavior, clipboard, and view preferences. |
| Command-line interface | Ships `keepassxc-cli` for database and entry workflows. | **Out of GUI scope / missing as a companion tool.** | Decide whether Nexus's Windows parity target includes a CLI; do not count it as a GUI blocker if the target is the desktop app only. |
| Platform-specific secret service | Integrates with FreeDesktop Secret Service on supported Linux desktops. | **Not Windows-targeted.** | No Windows parity work required. |

## Recommended implementation order

### P0 — Make database compatibility dependable

1. Define a supported KDBX compatibility matrix: KDBX versions, KDFs, ciphers, key-file formats, protected values, custom icons, tags, expiry, attachments, and history.
2. Add KeePassXC-generated fixtures and cross-application tests in both directions: open/edit/save in Nexus, then reopen and verify in KeePassXC; also verify KeePassXC-authored databases in Nexus. Include failure/tamper cases and files with features Nexus does not yet edit.
3. Resolve KDBX 3 save support and the experimental KDBX 4 writer limitation. Verify writes preserve unsupported-but-existing metadata rather than silently dropping it.
4. Harden file replacement, backup/recovery, and dirty-close behavior so a failed save cannot destroy the last good database.

### P1 — Complete core vault management

Add multiple open database tabs and recent files; full group lifecycle and ordering; entry clone and richer field editing; attachments, custom attributes, and visible/restorable history; and tag/favorite/recent navigation. Define behavior for recycle-bin and deletion before exposing destructive actions.

### P2 — Security and daily-use parity

Add TOTP setup/generation, consistent field-copy and clipboard auto-clear controls, lock-all/manual lock, broader search/filtering, database reports, and configurable password-generator rules. Extend inactivity locking to relevant Windows workstation/suspend events.

### P3 — Windows integrations and ecosystem features

Implement Auto-Type and its sequence/global-shortcut UX; browser integration and passkeys; YubiKey/OnlyKey challenge-response; import/export; and database merge/sync/KeeShare equivalents. Each item needs a Windows-specific security review and integration tests; these are not small UI-only additions.

### P4 — Product settings and operational polish

Add database key/KDF/cipher controls, backup/restore, keyboard-shortcut and view preferences, localization/accessibility coverage, and Windows packaging/file-association/update workflows. Decide separately whether to provide a companion CLI.

## Highest-risk parity concerns

- **KDBX write safety and interoperability:** The current dependency's experimental KDBX 4 writer and the client's KDBX 4-only save path are the most important blockers. A successful self-round-trip is not sufficient evidence that KeePassXC will preserve and reopen the result.
- **Unrepresented metadata:** Editing an entry or group without exposing attachments, custom attributes, history, recycle-bin state, or other KDBX metadata can cause compatibility loss unless the serializer preserves those values. Add preservation tests before broadening write support.
- **Secret exposure through integrations:** Auto-Type, browser messaging, clipboard, TOTP, passkeys, and breach-check reports expand the attack surface. They require explicit consent, data-flow constraints, lock-state checks, and tests for failure paths.
- **Synchronization conflicts:** Remote sync without a proper merge/conflict model risks lost updates or corrupt files. Implement and test merging before adding provider-specific sync.
- **Claims versus implementation:** The architecture specification describes planned secure storage, biometrics, cloud providers, browser extensions, and cross-platform clients. These must remain labeled as planned until present in the Windows app and verified end-to-end.

## Windows availability and integration caveats

Browser integration, passkeys, SSH Agent, networking, and update checks are build-configurable in KeePassXC; the repository defaults several of these on, but a specific installer can differ. The browser workflow depends on a separately installed extension and native-messaging host. Windows Hello quick unlock is a Windows-specific convenience feature, while KeeShare, Auto-Type, YubiKey/OnlyKey, and SSH Agent are distinct integration areas rather than interchangeable “plugin” capabilities. No general-purpose plugin manager was identified in the reviewed Windows GUI.

HIBP reporting is network-backed: KeePassXC's [report UI](https://github.com/keepassxreboot/keepassxc/blob/aabfb3858b98671e1f6ad1ffce70a418ba539fbc/src/gui/reports/ReportsWidgetHibp.ui) warns that it sends the first five characters of a password hash and the user's IP address to the service. Any equivalent Nexus feature should make that data flow explicit and opt-in. KeePassXC's [import/export guide](https://github.com/keepassxreboot/keepassxc/blob/aabfb3858b98671e1f6ad1ffce70a418ba539fbc/docs/topics/ImportExport.adoc) also warns that exported formats are unencrypted and can omit database features; Nexus should preserve those warnings and identify lossy formats before export.

## Bottom line

Nexus currently covers the basic offline vault and entry-editing workflow, plus the recently implemented icon, tag, and expiration features. To become a credible Windows KeePassXC alternative, first make KDBX writing/interoperability production-reliable, then complete core database/entry management and security workflows, and only then invest in browser, Auto-Type, hardware-key, and sync integrations.
